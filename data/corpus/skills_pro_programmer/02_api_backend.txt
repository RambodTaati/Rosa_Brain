# FastAPI / HTTP API professional practices
Design resources as nouns; use HTTP verbs correctly: GET safe, POST create, PUT replace, PATCH partial, DELETE remove.
Status codes: 200/201 success, 204 no body, 400 validation, 401 unauthenticated, 403 forbidden, 404 missing, 409 conflict, 422 unprocessable, 429 rate limit, 500 unexpected.
Error shape: {"error":{"code":"...","message":"...","details":[...]}} — stable codes for clients.
Validation: Pydantic models at the edge; reject unknown fields when appropriate; coerce carefully.
Pagination: limit/cursor or page/size; always cap max limit; return next_cursor when more exists.
Idempotency: Idempotency-Key header for POSTs that create; store response for replay; TTL the keys.
Auth cookies/sessions: prefer HttpOnly Secure SameSite cookies for browser sessions; do NOT store long-lived secrets in localStorage.
CSRF: for cookie sessions use SameSite=Lax/Strict and/or CSRF tokens on state-changing routes.
JWT access tokens: short-lived; refresh rotation; revoke lists when required; validate iss/aud/exp.
Authorization: check every handler; object-level checks (can user edit THIS row); deny by default.
CORS: explicit origins; never * with credentials; minimize allowed headers/methods.
Rate limiting: per user and per IP; return Retry-After; protect auth endpoints harder.
Migrations mindset: expand-contract; backward compatible deploys; never expand-and-break in one step.
DB sessions: one unit-of-work per request; commit on success; rollback on error; no lazy IO after response.
Background tasks: enqueue durable jobs for emails/webhooks; do not pretend in-process tasks are durable.
OpenAPI: keep schemas accurate; examples for tricky fields; version APIs via path or header intentionally.
Health: /healthz liveness, /readyz readiness (DB/queue); avoid heavy work on liveness.
File uploads: size limits, content-type allowlists, store outside web root, scan when policy requires.
Webhooks: verify signatures; idempotent handlers; respond quickly then process async.
Caching: Cache-Control on GETs; ETag/If-None-Match when useful; never cache personalized private data publicly.
Structured logging per request with request_id; propagate trace headers when present.
Secrets: load from env/secret manager; rotate; never commit .env with production secrets.
FastAPI deps: Depends for auth and DB; yield deps for cleanup; avoid global mutable request state.
Testing APIs: httpx/ASGITransport; fixture DB; assert status + error codes + authZ matrix.
Versioning: prefer additive changes; deprecate with timelines; document breaking changes.
Timeouts: set for outbound HTTP; circuit-break chronically failing deps.
Multi-tenancy: tenant id from auth context not from client-supplied body alone.
Soft deletes: explicit; unique constraints must consider deleted_at when needed.
Search endpoints: bound query cost; escape LIKE wildcards; prefer dedicated search indexes.
Batch endpoints: limit batch size; partial success semantics documented.
Feature flags: server-side; do not trust client flag overrides for security.
Admin routes: separate router, stronger auth, audit log mutations.
Cookies for SPA: CSRF strategy documented; SameSite; path=/; short session idle timeout.
localStorage: fine for non-secret UI prefs; NEVER for refresh tokens or session secrets.
