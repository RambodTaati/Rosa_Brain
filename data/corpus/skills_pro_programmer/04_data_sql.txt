# PostgreSQL modeling and data access
Model with clear primary keys; prefer BIGSERIAL/IDENTITY or UUID intentionally.
Normalize to reduce update anomalies; denormalize only with measured read needs and clear ownership.
Foreign keys enforce relations; ON DELETE behavior explicit (RESTRICT/CASCADE/SET NULL) — choose deliberately.
Indexes: B-tree for equality/range; composite order matches filters/sorts; partial indexes for hot subsets; unique for invariants.
Avoid over-indexing writes; monitor unused indexes.
Transactions: short, single purpose; SELECT ... FOR UPDATE when racing updates; serializable only when required.
Isolation: understand read committed defaults; watch write skew under higher isolation.
Parameterized queries always; never string-concatenate user input into SQL.
N+1: detect via logs; fix with joins, SELECT IN, or batched loaders.
Migrations: ordered, reversible when possible; expand-contract for zero-downtime; never edit applied migrations on shared envs.
Constraints: CHECK, UNIQUE, NOT NULL as close to data as possible.
JSONB: useful for sparse attrs; index with GIN when querying; do not replace core relational columns casually.
EXPLAIN (ANALYZE, BUFFERS) for slow queries; look for seq scans on large tables unexpectedly.
Connection pooling: pool size vs DB max_connections; idle timeouts; statement timeouts for safety.
Soft delete patterns: unique email where deleted_at is null via partial unique index.
Audit tables for sensitive mutations; who/when/what.
Backups: pg_dump logical; base backups for larger; test restores.
ORM: keep raw SQL available for hot paths; understand generated SQL.
Migrations mindset: add nullable column -> backfill -> add constraint; drop unused later.
