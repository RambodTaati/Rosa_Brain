# Testing and debugging mindset
Pyramid: many unit, fewer integration, few e2e; each layer catches different failures.
Unit: pure logic, fast, deterministic; no real network/disk unless tmp fixtures.
Integration: real DB in docker/tmp; exercise repositories and HTTP together.
E2E: critical user journeys only; stabilize with test ids; quarantine flakes.
Reproduce-isolate-fix: first reproduce reliably; minimize; then fix with a regression test.
Flaky tests: time dependence, order dependence, shared mutable state, real network — eliminate causes.
Logging for debug: temporary DEBUG with correlation ids; remove noise before merge.
Assertions: one main behavior per test; rich assertion messages; prefer equality on values.
Debuggers: breakpoints over print storms; bisect with git when regressions hide.
Contracts: consumer-driven ideas at API boundaries when multiple services.
Property tests for parsers and serializers.
Snapshot tests sparingly; they rot and rubber-stamp.
CI: fail on flake rate spikes; retry only with ticketed reason.
Load tests separate from functional; never confuse them.
Production debugging: read metrics/traces first; reproduce with redacted inputs.
