# C language essentials (original)

C is a low-level systems language. Many runtimes and databases are written in C. Web apps rarely use raw C for handlers, but understanding C helps with memory and APIs.
Hello: #include <stdio.h> int main(void) { printf("hi\n"); return 0; }
Types: int, char, float, double, void. Sizes are platform-dependent; use stdint.h (int32_t) when fixed width matters.
Pointers store addresses: int x = 3; int *p = &x; *p = 4;
Arrays decay to pointers in most expressions. Careful with lengths — C does not bounds-check.
Strings are null-terminated char arrays. Prefer snprintf over sprintf to limit writes.
Memory: malloc/free from stdlib.h. Always free what you allocate; set pointers NULL after free if reused.
structs group fields. typedef struct { int id; } Item;
Header files declare interfaces; .c files define them. Include guards or #pragma once.
Undefined behavior (buffer overflow, use-after-free) is catastrophic — defensive coding and tools (sanitizers) matter.
File I/O: fopen/fread/fwrite/fclose. Check return codes.
No exceptions: use return codes and errno conventions.
For web: C may appear in native modules, crypto libraries, or embedded devices speaking HTTP — still validate all inputs.
Practice: write a function that safely copies a string into a buffer with an explicit size using snprintf.
Q: Why is C risky with strings? A: Manual buffers without bounds checks lead to overflows; use sized APIs and checks.
Q: Who frees malloc memory? A: You do — every successful malloc needs a matching free on that path.
