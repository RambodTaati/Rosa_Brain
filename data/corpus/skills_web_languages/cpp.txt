# C++ essentials (original)

C++ builds on C with abstractions: classes, templates, RAII, and the standard library (STL).
Modern C++ (11–20): prefer RAII containers over raw new/delete. Use std::unique_ptr and std::shared_ptr when ownership is needed; prefer unique ownership.
#include <string> #include <vector> #include <iostream>
std::string s = "hello"; std::vector<int> v = {1,2,3};
Range-for: for (const auto& item : v) { ... }
classes with constructors/destructors; rule of zero/five for resource-owning types.
References int& r = x; must bind to valid objects. Const correctness: const std::string& for read-only params.
Templates enable generic code; concepts (C++20) constrain templates.
STL algorithms: std::find, std::sort, std::transform. Use <algorithm> and iterators or ranges.
Exceptions exist; many codebases limit throw across ABI boundaries. Be consistent.
Move semantics: std::move transfers resources; return local values rely on moves/elision.
For web backends, C++ appears in high-performance services; still sanitize inputs and use parameterized DB access via libraries.
Practice: RAII file wrapper sketch that closes in destructor.
Practice: count words in a std::string using stringstream or ranges.
Q: What is RAII? A: Bind resource lifetime to object lifetime so destructors release resources automatically.
Q: unique_ptr vs shared_ptr? A: unique_ptr is exclusive ownership; shared_ptr shares ownership with ref-counting — prefer unique when possible.
