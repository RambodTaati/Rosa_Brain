# XML and JSON (original)

JSON is the common data format for web APIs. XML remains in enterprise feeds, documents, and configs.
JSON types: object, array, string, number, boolean, null. No comments in standard JSON.
{"id": 1, "tags": ["a", "b"], "active": true}
Parse in JS: JSON.parse(text). Serialize: JSON.stringify(obj). Pretty: JSON.stringify(obj, null, 2).
Trailing commas are invalid in JSON. Keys must be double-quoted strings.
XML: tree of elements, attributes, text nodes. Declaration <?xml version="1.0" encoding="UTF-8"?>
<note id="1"><to>Ada</to><body>Hello</body></note>
Well-formed vs valid: well-formed follows XML syntax; valid also matches a schema (XSD/DTD).
Namespaces avoid element name clashes. CDATA wraps raw text blocks carefully.
XPath selects nodes in XML documents (tooling dependent).
When to choose JSON: APIs, configs for JS/Python, simplicity. When XML: document-centric data, existing SOAP/enterprise systems, mixed content publishing.
Security: XML external entities (XXE) can be dangerous — disable external entity resolution in parsers. For JSON, beware prototype pollution when merging objects unsafely in JS; validate shapes.
Content-Type: application/json and application/xml (or text/xml) — set correctly on responses.
Practice: convert a small XML note into equivalent JSON mentally and on paper.
Practice: detect invalid JSON (trailing comma) and fix it.
Q: Can JSON contain comments? A: Not in standard JSON; use JSONC only if your tooling explicitly supports it.
Q: What is XXE? A: An XML parser attack via external entities — disable external entities when parsing untrusted XML.
