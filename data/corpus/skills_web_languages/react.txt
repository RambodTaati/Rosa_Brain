# React essentials (original)

React builds UIs from components — functions that return element trees (JSX).
function Hello({ name }) { return <h1>Hello, {name}</h1>; }
JSX expressions go in {curly braces}. className instead of class. for -> htmlFor on labels.
Props are read-only inputs. State holds local data that changes over time.
import { useState, useEffect } from "react";
const [count, setCount] = useState(0);
setCount(c => c + 1) when next value depends on previous.
useEffect(() => { document.title = String(count); }, [count]); cleanup functions return from effects for subscriptions.
Lists need stable keys: items.map(item => <li key={item.id}>{item.label}</li>).
Conditional render: {isOpen && <Panel />} or ternary.
Controlled inputs: value={text} onChange={e => setText(e.target.value)}.
Events: onClick, onSubmit — handlers receive synthetic events; call preventDefault on forms when handling in JS.
Lifting state up: share state in the closest common parent. For distant sharing, consider context carefully (not a global dump).
memo/useMemo/useCallback are performance tools — measure before sprinkling them everywhere.
Fetching: useEffect with abort or a data library; handle loading/error states.
Routing and global data libraries are ecosystem choices (React Router, query libraries) — learn core first.
Defensive: do not dangerouslySetInnerHTML with untrusted HTML. Escape URLs; validate external links.
Practice: counter and a controlled text field that echoes length.
Practice: fetch-on-mount list with loading and error text (abort on unmount).
Q: Why keys in lists? A: Help React match children across renders; use stable ids, not array indexes when order changes.
Q: Props vs state? A: Props come from parents; state is owned and updated by the component (or a store).
